Architecture

A source neutral investigation pipeline

The public architecture describes responsibilities and data flow without exposing proprietary implementation details.

1. Input adapters

Defender XDR, Splunk alert JSON and email evidence are normalised at the boundary.

2. Canonical evidence

Common fields such as host, account, timestamp, indicators, timeline and confidence allow shared analysis/reporting.

3. Analysis engines

Context aware IOC handling, threat intelligence, MITRE mapping, evidence coverage and contradiction checks.

4. Evidence boundaries

The report explicitly records what the application could and could not determine from the supplied artefact.

5. Reporting

Stakeholder readable summaries sit alongside technical findings, limitations, investigation guidance and validation notes.

6. Proprietary boundary

Source code, API integration internals and detection heuristics are intentionally excluded from this public portfolio.
